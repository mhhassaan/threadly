> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Have deepseek-flash write every new thread, recover failed article extraction with DeepSeek Fetch, and enforce 2-total guest / 10-per-UTC-day verified allowances with one-time usage carryover.
**Architecture:** Keep the existing React/TanStack/Workers/D1 app. Server generation jobs provide idempotency, quota reservations and terminal results; a server-backed opaque guest cookie supports trial credits and an authenticated claim transfers completed usage. The client retains current thread saving/reading/export flows and never embeds provider credentials.
**Tech Stack:** Existing TypeScript, TanStack Start/Query/Router, Cloudflare Workers + D1, Better Auth, React; native fetch and Web Crypto. No new runtime dependency or remote resource.

## Review Focus
1. Claim while guest completion is committing: exactly one debit/result, no late guest publication or free account allowance (Tasks1,3,4).
2. A generation and a discussion admitted concurrently near global spend/account concurrency limits: combined cap holds (Tasks1,5).
3. A nominal200 article extraction is boilerplate or a provider returns truncated JSON: never create a fabricated/truncated thread (Tasks2,3).
4. Session pending/expiry/sign-out while generation response or account save arrives: no anonymous downgrade, private draft/export or duplicate saved thread (Tasks3,4).
5. UTC midnight, browser storage reset and deletion after completed generation: day semantics explicit, no accidental refunds or claims (Tasks1,5).
